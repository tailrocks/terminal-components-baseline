# P9.3 red and green records

Plan: the approved P9.3 design (v6) and test plan (v6), baseline lane,
steps B1 to B3. Each new test in this file ran twice: once with its named
break applied (red) and once on the committed code (green). The break is
one exact text replacement, shown as a diff, applied to a copy of the
tree and reverted. The red lines are the failing assertion and the
nextest summary. The green line is the nextest summary after the revert.

Reproduce one record:

```sh
mise exec -- cargo nextest run --locked --no-fail-fast \
  -p jackin-console --test <file> -E 'test(=<name>)'
```

Apply the break first, run, revert it, run again. Breaks touch library
source only, never an approved baseline. After the revert, touch the file
so the build sees it as changed.

Gate after each step: `cargo nextest run --locked --all-targets`,
`cargo clippy --locked --all-targets -- -D warnings`, `cargo fmt --check`,
and an empty `git diff --stat origin/feature/openshell-native --
tests/functional/baselines apps/jackin/tests/functional/baselines`.
