# P9.3 red and green records

Plan: the approved P9.3 design (v6) and test plan (v6), baseline lane,
steps B1 to B3. Each new test in this file ran twice: once with its named
break applied (red) and once on the committed code (green). The break is
one exact text replacement, shown as a diff, applied to a copy of the
tree and reverted. The red lines are the failing assertion and the
nextest summary. The green line is the nextest summary after the revert.

Reproduce one record:

```sh
mise exec -- cargo nextest run --locked --no-fail-fast \
  -p jackin-console --test <file> -E 'test(=<name>)'
```

Apply the break first, run, revert it, run again. Breaks touch library
source only, never an approved baseline. After the revert, touch the file
so the build sees it as changed.

Gate after each step: `cargo nextest run --locked --all-targets`,
`cargo clippy --locked --all-targets -- -D warnings`, `cargo fmt --check`,
and an empty `git diff --stat origin/feature/openshell-native --
tests/functional/baselines apps/jackin/tests/functional/baselines`.

## B4-0 review round: the flaky leak test and the fixes behind it

`showcase_fixed_controls_refuse_with_a_reason_and_never_leak_it` failed on the
unmodified commit `a1435ba`: 3 failures in 21 isolated runs, and 7 of 12 when run
with the other two fixed-control tests. The failing step was always `key space`
on the `Typed key` radio option, `timed out: status reads Not available · managed
by policy`.

Cause: the page returned `Outcome::Consumed` after a refusal, the showcase host did
not turn a posted status into `Changed`, and the runtime redraws only on `Changed`.
The new status painted only if a pointer flash or a status expiry repainted first.
The jackin console was not affected (its `apply_requests` returns `Changed`).

Fix, in the shared layer so no page has to remember it: `shell::handle` compares the
status line (text and tone) before and after each input and ORs in `Changed`; the
showcase host returns `Changed` when a page posts any request. The slot is also
cleared at the start of `handle`, not only at the end.

The tests that pin this round (keyboard-only redraw, the ListItem paths, the exact
neutral tone, the sticky status, the Dialog fixed action) are recorded in the next
section.
