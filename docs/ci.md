# CI

CI is generated by velnor-actions 0.1.73 from `.velnor/config.toml`.
Never hand-edit `.github/workflows/`, `.github/actions/`,
`.github/scripts/`, `.github/velnor/`, `.github/actionlint.yaml` or
`.github/AGENTS.md`; change the config and run `velnor-actions generate`.

## Gates

- **Plan** — computes the job matrix (15-minute timeout; the full
  history checkout is large).
- **Suite (functional)** — the pull_request and push gate, and the
  workflow_dispatch tier on `suites.yml`. Both generated jobs run
  `mbx nextest run --workspace --no-tests fail --profile functional`.
  That is the exact argv inside the `Run suite (functional)` step in
  `.github/workflows/ci.yml` and `.github/workflows/suites.yml`.
  `--profile functional` selects
  `[profile.functional] default-filter = 'binary(functional)'` in
  `.config/nextest.toml`, so the functional inventory runs without a
  suite filter. `--no-tests fail` stays because the suite is not
  sharded and has no filter. `partitions = 1` stays written in
  `.velnor/config.toml`; velnor-actions then emits one job and does
  not add `--partition`, so one failure fails that job.
  `required = true` adds `suite-functional` to the generated
  `required` verdict job (`needs` and `VELNOR_NEEDS_EXPECTED`). The
  generator does not call the GitHub branch-protection API.
  `functional-terminal-evidence` uploads `target/functional` and
  `target/nextest/functional` with `when = "always"` (`if: always()`)
  and `retention_days = 14`.

  The local command in
  [functional testing](functional-testing.md) still passes `--locked`.
  The generated suite command does not. velnor-actions 0.1.73
  `RustSuiteConfig` has no suite argv field (`deny_unknown_fields`,
  no `extra_args`). mr-boxington 1.29.1 does not inject `--locked`:
  `run_cargo` forwards the caller arguments, and `mbx nextest run
  --help` lists `--locked` as an optional Cargo flag.

  `scripts/check-refactor-coverage.py` cannot be added as a generated
  step, and it must not be a required check yet.
  `docs/testing/refactor-coverage.json` has 2223 rows, all `BLOCKED`,
  and the script exits 1 in that state. Missing committed baselines
  are already detected by the functional tests through Tuiscotti
  `FrozenStore` (`tests/functional/support.rs`).

  macOS and Windows are unclaimed. This generated suite has one
  `runner_label` (`ubuntu-26.04`) and no OS matrix. No runner label
  was invented for the other systems.

  `RustSuiteConfig` supports `schedule`, but this suite leaves it
  empty. A cron would be another trigger on the existing suites
  workflow, not an additional workflow, and the required gate is
  already on pull_request and push.

  Branch protection is unverified. Read-only `gh api` against
  `repos/tailrocks/terminal-components-baseline/branches/test/pre-refactor-protection/protection`
  and `.../branches/design/interaction-polish/protection` both
  returned HTTP 404
  `{"message":"Branch not protected","documentation_url":"https://docs.github.com/rest/branches/branch-protection#get-branch-protection","status":"404"}`.
  `gh api repos/tailrocks/terminal-components-baseline/rulesets`
  returned `[]`.
- **Rust / junie-tui** — one crate job. Format, clippy, unit and
  integration tests, and documentation run in that job. The generator
  no longer emits a separate read job and write job.
- **DCO** — every commit must carry `Signed-off-by`
  (`git commit -s`, committer Alexey Zhokhov
  <alexey@zhokhov.com>).

Local equivalents are in [development](development.md). Tool pins
live in `mise.toml`; install with `mise install`.
